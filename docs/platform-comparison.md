# 知识库应用选型对比：Dify vs RAGFlow vs MaxKB

> 本项目选型结论：**用 Dify 做深度落地**。为什么不是 RAGFlow 或 MaxKB？本文从定位、RAG 能力、编排能力、工程化等维度做横向对比，并给出选型依据——这也是面试中"你只用过 Dify，凭什么说熟悉主流知识库应用？"的答案。

## 一句话定位

| 平台 | 定位 | 最适合的场景 |
|---|---|---|
| **Dify** | LLM 应用**编排**平台（Workflow/Agent + 知识库 + 工具生态） | 多步骤任务编排、Agent + 工具调用、需要把 LLM 应用发布为 API 的场景 |
| **RAGFlow** | 深度**文档理解** RAG 引擎（DeepDoc 解析 + 引用溯源） | 大量复杂格式文档（PDF 表格/扫描件/论文）的高保真问答与溯源 |
| **MaxKB** | 开箱即用的**企业知识库问答**系统（基于 LLM + RAG） | 中小团队快速上线客服/内部知识问答，强调易用与权限管理 |

## 维度对比

| 维度 | Dify | RAGFlow | MaxKB |
|---|---|---|---|
| 核心抽象 | **应用 + 工作流画布**（节点编排） | **知识库 + 对话**（解析为中心） | **知识库 + 应用问答** |
| 文档解析 | 常规解析（依赖 Unstructured 等） | ★ DeepDoc：版式分析、表格结构还原、OCR | 常规解析 |
| 分块控制 | 父子分块、自定义分隔符、Q&A 模式 | 模板化分块（论文/书籍/法律/表格） | 分段规则较简化 |
| 检索 | 向量 / 全文 / **混合检索 + 重排**（多路召回可调权重） | 全文 + 向量混合，引用定位到原文片段 | 向量检索为主 + 可配相似度阈值 |
| 多轮编排 | ★ Workflow / Chatflow / Agent（迭代、分支、变量、代码节点） | Agentic RAG 工作流（v0.20+，偏检索增强） | 函数库与简单工作流（v1.10+） |
| 工具/集成 | ★ 50+ 内置工具 + 自定义 OpenAPI 工具 + MCP | API / SDK，工具生态较弱 | API / SDK，嵌入第三方应用方便 |
| 模型接入 | ★ 模型市场插件化（DeepSeek/Qwen/本地 Ollama/Xinference 等） | 主流 LLM + 本地模型 | 主流 LLM + 本地模型 |
| 发布形态 | ★ 发布为 WebApp / **Service API** / 嵌入组件 | Web UI + API | Web UI + API + 嵌入脚本 |
| 运维成本 | docker compose 一键起；有云端托管 | 组件多（含 ES/Infinity、MinIO），资源要求较高 | 单容器轻量，最易部署 |
| 开源协议 | 基于 Apache 2.0 修改（多租户限制） | Apache 2.0 | GPL v3（二开需开源） |

## 为什么本项目选 Dify

本项目的核心诉求排序：**多阶段任务编排 > 外部工具集成 > 知识库检索 > 文档解析**。

1. **任务编排是刚需**：文献筛选管线是"知识检索 → LLM 解析 → 检索式组装 → 外部 API 检索 → 迭代逐篇判定 → 汇总报告"的十节点流程，需要迭代节点、代码节点、变量传递、分支重试——只有 Dify 的 Workflow 能完整表达（RAGFlow/MaxKB 以"知识库问答"为中心，编排能力弱一档）。
2. **外部工具集成是刚需**：PubMed 检索必须作为外部 API 工具接入，Dify 原生支持 OpenAPI Schema 注册自定义工具；RAGFlow/MaxKB 无对等的工具生态。
3. **知识库在本项目里是"辅助角色"**：MeSH 主题词库是小而规整的结构化文本（每条一个 Term+同义词+定义），不存在复杂版式解析需求——RAGFlow 的 DeepDoc 优势用不上；Dify 的混合检索 + bge-m3/bge-reranker 完全够用。
4. **交付形态**：需要把整条管线发布为 API 给客户端调用（Service API + SSE 流式），Dify 一键发布。

## 什么时候应该反过来选另外两个

- 语料以**扫描件 PDF、复杂表格、多栏论文**为主，且要求**答案逐句溯源到原文** → RAGFlow（DeepDoc 解析 + 引用定位是它独有的护城河）。典型：病历文书、合同审阅。
- 需求就是"**把公司文档传上去，客服/员工直接问答**"，要最快上线、最少运维、带团队权限管理 → MaxKB。典型：企业内部 FAQ、政务/校园知识问答。
- 实际工程里三者可以组合：MaxKB/RAGFlow 做知识库前端，通过 API 作为 Dify 的**外部知识库**接入编排层——Dify 支持外接知识库（External Knowledge API）。

## 面试速答（30 秒版）

> "三个平台我都做过选型评估：MaxKB 是轻量知识库问答、RAGFlow 强在复杂文档解析和引用溯源、Dify 强在工作流编排和工具生态。我的文献筛选场景核心是多阶段编排加外部 PubMed 工具集成，知识库只是辅助检索 MeSH 主题词，所以 Dify 是最优解；我实际用它搭了十节点工作流，包括迭代逐篇筛选和自定义 API 工具。如果场景换成扫描件病历问答，我会选 RAGFlow。"
